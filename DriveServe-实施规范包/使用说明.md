# 规范包使用说明

本包用于放入算力平台上的 DriveServe 项目，指导 agent 自主实施六阶段目标。主规范当前为 1.1 版，已补充环境迁移、数据用途与阶段内保存/恢复最低规则。当前仅生成了规范，所有项目要求状态均为待执行。

## 包内文件

| 文件 | 用途 |
|---|---|
| `AGENTS.md` | agent 的简短实施入口 |
| `docs/DriveServe-实施与验收规范.md` | 主规范，包含目标叙事、六线最低要求、六阶段验收、实验与留迹、累计讲解要求 |
| `docs/progress.md` | 初始进度记录，接管后由 agent 持续更新 |
| `docs/coverage.md` | 27 项最低要求的初始覆盖矩阵 |

## 放入项目

1. 在算力平台创建或打开 DriveServe 项目目录。
2. 将本包中的 `AGENTS.md`、`docs/` 和本说明复制到该项目根目录。压缩包带有一层 `DriveServe-实施规范包/` 目录，复制的是该目录里面的内容。
3. 如果项目已有同名文件，先比较并合并；不要覆盖已有 agent 规则、用户文件或真实进度。
4. 在平台 agent 中明确启动实施。不要把规范中的目标数字或初始模板理解成现成代码和成绩。

建议启动提示：

> 阅读 AGENTS.md 与 docs/DriveServe-实施与验收规范.md，检查当前环境和已有文件，从真实进度开始按六阶段目标推进。具体实现由你设计；持续提交关键工作，记录实验和资产，维护进度、覆盖矩阵与累计讲解。常规已授权工作自主继续，遇到需要新增预算或改变范围的问题再提交具体选择。所有完成状态和指标必须有实际证据。

## 执行前的信息

已知：每天约 9 小时，2×RTX 4090 约一个月，最终深度参考研三学生四个月工作量。实际租期起止、机器配置、模型访问、存储、Git 作者信息、GitHub remote 等由 agent 检查，无法获知且必要的信息再向用户询问。

租期内 GPU 可能间歇不可用，或在平台标注的双卡 24GB/48GB 实例之间迁移。agent 应核实持久存储并建立固定、可恢复/重建的环境，迁移后检查兼容性与重新测量；无卡期间继续可独立工作。数据可公开获取、自建或混合，但须分别满足性能、质量、校准和蒸馏的用途与隔离要求。具体方案由 agent 决定。

这些信息不齐不妨碍可独立开展的本地工作，但 agent 不得自行购买资源、伪造身份、公开仓库或声明尚未运行的 GPU 实验成功。

## 中断或换对话后

让接管 agent 重新读取入口、主规范、进度及覆盖矩阵，并核对 Git、环境、实际任务和资产后继续。执行期间须按主规范第 9.7 节进行事件和周期保存，并验证恢复能力；不需要靠多个并行对话续接单个阶段。自动重启或守护是否部署另行记录，规范包本身不会启动或唤醒 agent。

## 阶段结束时应能看到什么

- 明确的完成/验收状态和可定位的版本。
- 对应功能、实验与原始证据。
- 更新后的进度和覆盖矩阵。
- 一份从项目开始到当前阶段的完整讲解材料。
- 当前可用的事实版简历，以及每条表述对应的实现和实验。

本规范采用六阶段方案，替代此前十阶段串行路线。基础版自阶段 2 起完整覆盖六条主线；此后增加深度和证据，不静默删除主线。

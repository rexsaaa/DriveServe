# DriveServe最终工程报告

S1–S6已经验收，最终发布版本为v1.0.0。项目完成结构化车载决策代理任务上的六条推理工程主线；它没有感知—规划—控制闭环或真实车辆安全结论。完整原始结果与阶段版本见[索引](results-index.md)，27项最低要求见[覆盖](coverage.md)。

六条主线分别具备固定源码调用链与运行插桩、真实KV冷热与长度调度、运行时K及实际Draft序列蒸馏、自主AWQ校准与敏感性分析、独立融合CUDA算子、FA2/Nsight与三部署对照。上游能力和个人增量分开记录。S4进一步完成保持策略顺序的heap索引与head tile/half2 CUDA消融；大池维护收益、额外内存、长尾与大shape退化均保留。[累计讲解](stages/S6/README.md)解释从最小闭环到深入版本的实现、错误与权衡。

最终GPU侧证据包括39个正式计时进程、9216/9216 HTTP请求完成、十profile各256条最终质量，以及最后十项CPU/allocator/CUDA/Graph回归。最终十组均输出256个有效JSON、236条规则正确；四spec与各自Target全部token/结束一致，调度两组各两条只有JSON空白差异。事前门槛没有根据测试结果改变。[最终质量](../reports/s5-final-quality.json)不是实车安全或跨模板泛化证明。

在原生APC/Graph基线上，FP16 Target/fixed/adaptive三轮总wave均值约15.371/13.365/13.105s，推测的平均首字延迟增加；动态K相对fixed的增量方向跨轮变化。AWQ Target约9.762s，AWQ fixed/adaptive约16.344/16.572s，组合三轮均更慢。不能相加量化和推测的单项收益。自研冷热在自然业务没有额外复用，合成热点压力中的机制结果与长请求代价单独报告；独立CUDA未接服务。[主表](s5-results.md)保留标准差、逐轮P99与质量。

开环自然高rate下，TP2的探索性尾延迟低于轮询双副本，但三种部署都存在大量未满足事前SLO的完成请求。自然业务每cell242/256正确，填充压力204/256；填充有可复用公共前缀且采用不同SLO，不能将其吞吐当真实业务收益。每cell256×3不足以承诺生产稳定P99，S3 TP2首轮异常波动的原因仍未确定。[组合与部署讨论](s5-discussion.md)明确观测与因果推断的边界。

最终默认保留FP16 Target/native APC；领域group128 AWQ和FP16推测是有条件的独立profile，AWQ×spec默认关闭，heap不替换小池scan。未验证自研策略×spec×TP2的统一进程。准确命令与范围见[最终配置矩阵](s5-compatibility.md)和[配置文件](../configs/final-profiles.json)。

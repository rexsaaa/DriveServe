# S3 事前验证与独立重复协议

进入条件：S2 accepted且stage-2-minimum已推送读回。S2六线profile保持可运行，不访问final-test，不更换模型家族、任务schema或标签。S3完善证据可信度，不把扩大样本/换后端直接称创新；S4另外选择至少两项实质深化。

## 重复与口径

主表每配置3个独立进程运行，重复编号1/2/3，固定输入和seed，按预定轮换顺序交错配置。每次重新初始化引擎，加载/Graph/warmup在外；timing开始前两GPU空闲，无AWQ校准、训练或OSS传输，Nsight/trace和正式计时分开。每轮保留全部失败和差异，失败重测使用新run，不合并中断片段。

报告每次绝对值及run级均值、标准差、min/max；算子同时保留进程内原始Event样本。3次独立运行仍不构成稳定生产P99：服务每cell64请求，按run列出尾部，不把192混合样本当192独立环境重复。输出长度和质量改变时同时报告req/s、完成时间和质量，禁止只按token/s说等工作量加速。正式结论使用原生B1，保留B0和失败修复的边界。

## 各主线预定工作

| 主线 | 独立重复 | 扩展边界及其他证据 |
|---|---|---|
| M1 | B1 native trace on/off各3次，同波次/输出，主机方法与GPU计时分开 | 保留异常输入、HTTP错误/超时/不完整SSE的失败分母；重聚合每次结果 |
| M2 | Graph/4原生B1、cache、scheduler、both各3次 | lifecycle native/both实际共享/取消/抢占/重用；独立真实allocator；汇总维护扫描和admission成本、短长组等待，不隐藏长组退化 |
| M3 | Target、原Draft fixed、新Draft fixed、新Draft adaptive各3次；先检查Graph可用性后固定编译模式 | 动态batch/EOS/拒绝/长度/上下文、实际K轨迹；支持编译模式实测；固定分布采样检查与训练数据隔离重新核对；不重复训练冒充进展 |
| M4 | FP16、general128、domain128、domain64原生AWQ各3次，固定KV；选定domain128与原生awq_marlin后端对照 | domain128独立重新校准一遍，比较实际权重hash/局部误差；记录不能续AWQ的边界；固定总预算容量沿用S2同环境真实数据，无无意义重复 |
| M5 | 原CUDA实现48正确性+6形状Event各3进程 | 非法dtype/shape/stride/alias、slot/position边界；独立memcheck；继续按固定上游能力核查，不声称服务接入 |
| M6 | single/replica/tp2各3次，512/1536×1/8，预算与路由不变；FA2八形状3次 | 校验服务后端/Graph日志；诊断TP2 dev-030差异；按相同前缀/配置采分数，未解释差异则不启用为等质量替换 |

选定模型质量门槛在最终测试前冻结：无填充的完整dev128必须全部请求完成且JSON有效，oracle正确数不低于同模式FP16基线1条（S2为121，则至少120）。这只是小开发集合的容忍阈值；不能称统计非劣效或安全保证。量化/推测若失败则保持FP16 Target默认并记录负结果；来源/group不再因final-test重选。合成填充部署矩阵另报其显著降质，不以它替代业务质量门槛。

M3 Graph若版本限制导致无法通过，保留失败并明确eager-only支持，比较优化时仍展示合理Graph原生B1，不能关闭Graph制造加速；S3不能把未验证编译模式写支持。TP2长填充差异先诊断，不擅自改标签或删样本。后端改动同样须实测数值和质量，不把Marlin原生能力当个人kernel创新。

## 留存和衔接

运行时每波/每cell落盘，包装器30秒心跳；校准每层落盘，完整导出原子校验。若重复AWQ权重与已备份内容逐字节相同，可复用既有OSS对象并记录来源映射，不上传重复付费副本；如不同则按项目授权另存独立前缀。不能先删除唯一副本。

完成时提供稳定性报告、失败/回归表、更新的六线累计讲解和事实简历，逐条审查S3验收条件后才打tag。至少两个S4候选须依据本次实测成本/退化选择，不能将S3多跑参数当深化完成。

执行顺序在configs/s3-timing-plan-r1/r2/r3.json中冻结，每轮18个独立进程单元，各组按轮号循环移位。FP16 Target Graph同一run兼作M3和M4基线，避免重复相同工作。先验证Graph与Marlin可用再计时；run_experiment_plan.py逐项验证GPU空闲和无其他实验/备份进程，30秒保存计划状态。每轮源码冻结，轮间再提交结果；失败保存并停下检查，重测整单元。

当前第一轮18/18完成；聚合脚本经真实回放修复路径/返回值接入并核对39指标组。第二轮开始补任务前后温度、功耗、频率快照，不补造第一轮遥测。该观测加入包装器，不改内部引擎或计时函数。configs/s3-boundary-plan.json为正式计时之外的9项诊断，包含CPU协议、留存数据隔离、allocator、Graph lifecycle native/both、both维护trace、memcheck与随机Graph target/adaptive；不从诊断时长作性能结论。
